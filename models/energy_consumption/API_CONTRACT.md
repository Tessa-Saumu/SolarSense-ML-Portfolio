## Model 1 – Energy Consumption ML API Contract (`app_ml.py`)

This document is the authoritative backend contract for the **ML-based Model 1 Energy Consumption API** implemented in `src/app_ml.py`.  
It reflects the **current code** only – no assumptions.

---

### 1. Base URL & Versioning

- **Local base URL (default):** `http://localhost:8001`
  - Host: `0.0.0.0`
  - Port: `MODEL1_PORT` environment variable (defaults to `8001` if unset)
- **Versioning prefix:** All endpoints are under **`/api/v1/`**.

---

### 2. Authentication & Security

- **Authentication mechanism:** API key header
  - Header name: **`X-API-KEY`**
  - Expected value: environment variable **`API_KEY`** (loaded via `python-dotenv`)
- **Required headers:**
  - `Content-Type: application/json` (for JSON requests)
  - `X-API-KEY: <your-api-key>` (for all protected endpoints)
- **Endpoints requiring API key:**
  - `POST /api/v1/estimate-consumption`
- **Endpoints not requiring API key:**
  - `GET /api/v1/health`
- **Behavior when API key is missing or invalid:**
  - Returns **401 Unauthorized** with JSON body:

```json
{
  "error": {
    "code": "UNAUTHORIZED",
    "message": "Invalid or missing API key",
    "status": 401
  }
}
```

- **Behavior when `API_KEY` is not configured on the server:**
  - Returns **500 Internal Server Error** with JSON body:

```json
{
  "error": {
    "code": "AUTH_ERROR",
    "message": "Server configuration error",
    "status": 500
  }
}
```

---

### 3. Rate Limiting

- **Library:** `Flask-Limiter`
- **Key function:** `get_remote_address` (per-client IP)
- **Default limit:** **`100 requests per minute`** per IP
- **Applied to:**
  - `POST /api/v1/estimate-consumption`
- **Rate limit exceeded behavior:**
  - HTTP status: **429 Too Many Requests**
  - Response body: **plain text/HTML** generated by Flask-Limiter (not JSON)
  - Example body (approximate): `"429 Too Many Requests: Rate limit exceeded"`

> Note: 429 responses **are not JSON** in the current implementation.

---

### 4. Endpoints Overview

#### 4.1 Health Check

- **Endpoint:** `GET /api/v1/health`
- **Auth:** Not required
- **Rate limiting:** Default limiter applies (100/min)
- **Request body:** None
- **Successful response (200):**

```json
{
  "status": "healthy"
}
```

#### 4.2 Energy Consumption Estimate (ML)

- **Endpoint:** `POST /api/v1/estimate-consumption`
- **Auth:** `X-API-KEY` required
- **Rate limiting:** 100 requests per minute per IP
- **Content-Type:** `application/json`
- **Request body:** JSON object (see schema below)
- **Main behavior:**
  - Maps simple SME inputs to ML feature space
  - Predicts **annual** kWh with a Gradient Boosting model (optionally log-transformed target)
  - Applies climate factor based on location
  - Converts to **monthly** kWh
  - Enforces refrigeration share between 50–70%
  - Returns breakdown and confidence score

---

### 5. Request Schema (`POST /api/v1/estimate-consumption`)

#### 5.1 Fields

| Field                    | Type    | Required | Constraints / Notes                                                                                  |
|--------------------------|---------|----------|-------------------------------------------------------------------------------------------------------|
| `business_type`          | string  | yes      | Must be one of: `"butchery"`, `"grocery"`, `"mini_supermarket"` (case-insensitive input, lowered in code). |
| `sqft_m2`                | number  | yes      | Parsed as `float`. Must be **> 0** and **≤ 10000** (m²).                                             |
| `operating_hours_weekly`| number  | yes      | Parsed as `float`. Must be **> 0** and **≤ 168** (hours in a week).                                  |
| `num_refrigeration_units`| integer| yes      | Parsed as `int`. Must be **≥ 0** and **≤ 500**.                                                      |
| `location`               | string  | yes      | Must be a string. Length must be **≤ 200** characters. Used for climate factor (city substring).     |
| `num_workers`            | integer | no       | Parsed as `int`. If missing/invalid → defaults to `5`. If ≤ 0 → reset to `5`. Must be **≤ 1000**.    |
| `months_per_year`        | integer | no       | Parsed as `int`. If missing/invalid → defaults to `12`. If ≤ 0 or > 12 → reset to `12`.             |

#### 5.2 Derived / Internal Values (not in request)

These are computed internally and **not** part of the public request schema:

- `sqft` = `sqft_m2 * 10.764`
- `sqft_per_worker`
- `wkhrs_per_week_normalized`
- `annual_operating_hours`
- `refrigeration_density`
- `is_high_refrigeration`
- `is_extended_hours`
- `size_category` ∈ {"small", "medium", "large"}
- Encoded features via label encoders (`le_pba`, `le_cendiv`, `le_size`)

---

### 6. Response Schema (`POST /api/v1/estimate-consumption`)

#### 6.1 Successful Response (200)

```json
{
  "estimated_consumption_kwh_monthly": 335.25,
  "confidence_score": 0.85,
  "breakdown": {
    "refrigeration": 201.15,
    "other": 134.1
  },
  "climate_adjustment_factor": 1.35,
  "equipment_summary": {
    "total_refrigeration_units": 3,
    "total_other_equipment": 0
  }
}
```

> Values above are illustrative; actual numbers depend on the trained model and inputs.

#### 6.2 Field Definitions

| Field                                   | Type    | Description                                                                                               |
|-----------------------------------------|---------|-----------------------------------------------------------------------------------------------------------|
| `estimated_consumption_kwh_monthly`     | number  | Total **monthly** electricity consumption (kWh). Derived from annual ML prediction × climate factor / 12. |
| `confidence_score`                      | number  | Heuristic confidence score in [0, 1]. Defaults to 0.75; becomes 0.85 when core inputs are valid/positive.|
| `breakdown.refrigeration`              | number  | Monthly kWh attributed to refrigeration (50–70% of total, enforced by heuristic).                        |
| `breakdown.other`                      | number  | Monthly kWh attributed to all other uses.                                                                 |
| `climate_adjustment_factor`            | number  | Multiplicative factor based on `location` (1.18–1.35 for known cities, `1.20` default).                  |
| `equipment_summary.total_refrigeration_units` | integer | Echo of `num_refrigeration_units` from request.                                                           |
| `equipment_summary.total_other_equipment`     | integer | Always `0` in current implementation (not tracked).                                                       |

#### 6.3 Output Validation Rules

From the current implementation:

- `estimated_consumption_kwh_monthly`:
  - If negative → reset to `0.0`
  - If > `1_000_000` → capped to `1_000_000.0`
- `breakdown.refrigeration` and `breakdown.other`:
  - Clipped to be **≥ 0.0**
- `confidence_score`:
  - Clipped to `[0.0, 1.0]`

### 7. Error Responses

All error responses from `estimate_consumption` are JSON, **except** 429 rate limit responses, which are plain text/HTML from Flask-Limiter.

#### 7.1 400 – Invalid JSON

Conditions:
- Malformed JSON body
- Empty body with `Content-Type: application/json`

Response:

```json
{
  "error": {
    "code": "INVALID_JSON",
    "message": "Request body must be valid JSON",
    "status": 400
  }
}
```

#### 7.2 400 – Missing Required Field

Condition:
- Any of the required fields is missing: `business_type`, `sqft_m2`, `operating_hours_weekly`, `num_refrigeration_units`, `location`.

Response:

```json
{
  "error": {
    "code": "MISSING_FIELD",
    "message": "Missing required field: sqft_m2",
    "status": 400
  }
}
```

> The field name in `message` reflects the first missing field discovered in the validation loop.

#### 7.3 400 – Invalid Field Type

Conditions:
- `business_type` is not a string
- `sqft_m2` cannot be parsed as float
- `operating_hours_weekly` cannot be parsed as float
- `num_refrigeration_units` cannot be parsed as int
- `location` is not a string

Examples:

```json
{
  "error": {
    "code": "INVALID_FIELD_TYPE",
    "message": "sqft_m2 must be a number",
    "status": 400
  }
}
```

```json
{
  "error": {
    "code": "INVALID_FIELD_TYPE",
    "message": "location must be a string",
    "status": 400
  }
}
```

#### 7.4 400 – Invalid Field Value

Conditions:

- `sqft_m2 <= 0`
- `sqft_m2 > 10000`
- `operating_hours_weekly <= 0` or `> 168`
- `num_refrigeration_units < 0` or `> 500`
- `num_workers > 1000`
- `location` length > 200 characters

Examples:

```json
{
  "error": {
    "code": "INVALID_FIELD_VALUE",
    "message": "sqft_m2 exceeds maximum allowed value (10,000 m²)",
    "status": 400
  }
}
```

```json
{
  "error": {
    "code": "INVALID_FIELD_VALUE",
    "message": "num_refrigeration_units exceeds maximum allowed value (500)",
    "status": 400
  }
}
```

#### 7.5 400 – Invalid Business Type

Condition:
- `business_type` not in `["butchery", "grocery", "mini_supermarket"]` (after `.lower()`).

Response:

```json
{
  "error": {
    "code": "INVALID_BUSINESS_TYPE",
    "message": "Invalid business_type. Must be one of: ['butchery', 'grocery', 'mini_supermarket']",
    "status": 400
  }
}
```

#### 7.6 401 – Unauthorized (Invalid or Missing API Key)

See **Authentication & Security** section above.

#### 7.7 415 – Unsupported Media Type

Condition:
- Request body is not JSON and `Content-Type` is not `application/json`.

Response:

```json
{
  "error": {
    "code": "UNSUPPORTED_MEDIA_TYPE",
    "message": "Content-Type must be 'application/json'",
    "status": 415
  }
}
```

#### 7.8 429 – Too Many Requests

Condition:
- More than 100 requests/minute per IP to `POST /api/v1/estimate-consumption`.

Behavior:
- HTTP status: **429 Too Many Requests**
- Body: **non-JSON** text/HTML produced by Flask-Limiter (no custom handler is defined).

#### 7.9 500 – Internal Server Error (Prediction Errors)

Conditions:
- Model/scaler not loaded (`best_model` or `scaler` is `None`)
- Any exception raised during feature encoding, scaling, or prediction

Response (for all 500s from `estimate_consumption`):

```json
{
  "error": {
    "code": "PREDICTION_ERROR",
    "message": "Internal Server Error",
    "status": 500
  }
}
```

> Internal error details and stack traces are **logged server-side** but never exposed in the JSON response.

### 9. Security Notes

- **API key** must be treated as a secret:
  - Stored in `.env` as `API_KEY`
  - Never logged, committed, or exposed to clients
- **Rate limiting** protects the service from abuse:
  - 100 requests per minute per client IP
- **Input validation** rejects:
  - Out-of-range numeric values (e.g. extremely large `sqft_m2` or `num_workers`)
  - Invalid types and missing required fields
- **Output validation** ensures:
  - No negative energy values
  - Confidence scores stay within [0, 1]

---

### 10. Versioning Notes

- All current endpoints are under **`/api/v1/`**.
- Any breaking changes in request/response schemas should be introduced under a new prefix (e.g. `/api/v2/`).
- Existing `/api/v1/` behavior should be considered stable for current integrations.
