# Integration Guide: Solar Generation Prediction API

This guide provides everything you need to integrate the Solar Generation Prediction API into your Node.js/Express backend.

---

## 1. Prerequisites

### Python Version
- **Python 3.8+** (tested with Python 3.9 and 3.10)

### Python Dependencies
All dependencies are listed in `requirements.txt`. Core packages:

- `Flask>=3.0.0` - Web framework
- `Flask-CORS>=4.0.0` - CORS support
- `Flask-Limiter>=3.5.0` - Rate limiting
- `python-dotenv>=1.0.0` - Environment variable loading
- `joblib>=1.3.0` - Model serialization
- `numpy>=1.24.0` - Numerical operations
- `xgboost>=1.7.0` - ML model library
- `pandas>=2.1.0` - Data processing (for training pipeline, not required for API runtime)

### Required Environment Variables
- `API_KEY` (required) - Secret key for authentication
- `MODEL_DIR` (optional, default: `models`) - Directory containing model artifacts
- `PORT` (optional, default: `8000`) - Flask server port

### External Dependencies
The API requires three model artifact files in the `models/` directory (or path specified by `MODEL_DIR`):

1. `xgboost_climatological_model.pkl` - Trained XGBoost model
2. `feature_columns.pkl` - Feature column order
3. `xgboost_climatological_metadata.json` - Model metadata (training date, MAPE, etc.)

These files are generated by the training pipeline and should already be present in the repository.

## 4. Calling the API from Node.js

### Complete Working Example

Here's a complete Express route handler that calls the solar generation API:

```javascript
const axios = require('axios');

// Configuration
const SOLAR_API_BASE_URL = process.env.SOLAR_API_BASE_URL || 'http://localhost:8000';
const SOLAR_API_KEY = process.env.SOLAR_API_KEY; // Must be set in your .env

/**
 * Predict solar generation for a location
 * @param {number} latitude - Latitude (-26 to 6)
 * @param {number} longitude - Longitude (-18 to 44)
 * @param {number} [month] - Optional month (1-12). If omitted, returns full 12-month climatology
 * @param {boolean} [includeLifetime=true] - Include 25-year lifetime projection
 * @returns {Promise<Object>} Prediction response
 */
async function predictSolarGeneration(latitude, longitude, month = null, includeLifetime = true) {
  try {
    const response = await axios.post(
      `${SOLAR_API_BASE_URL}/api/v1/predict-generation`,
      {
        latitude,
        longitude,
        ...(month !== null && { month }),
        include_lifetime: includeLifetime,
      },
      {
        headers: {
          'Content-Type': 'application/json',
          'X-API-KEY': SOLAR_API_KEY,
        },
        timeout: 10000, // 10 second timeout
      }
    );

    return response.data;
  } catch (error) {
    if (error.response) {
      // API returned an error response
      const { status, data } = error.response;
      
      if (status === 400) {
        throw new Error(`Validation error: ${data.message}`);
      } else if (status === 401) {
        throw new Error('Unauthorized: Invalid or missing API key');
      } else if (status === 500) {
        throw new Error('Server error: Model service unavailable');
      } else {
        throw new Error(`API error (${status}): ${data.message || 'Unknown error'}`);
      }
    } else if (error.request) {
      // Request was made but no response received
      throw new Error('Network error: Could not reach solar generation API');
    } else {
      // Error setting up the request
      throw new Error(`Request setup error: ${error.message}`);
    }
  }
}

// Express route example
app.post('/api/solar/predict', async (req, res) => {
  try {
    const { latitude, longitude, month, includeLifetime } = req.body;

    // Validate required fields
    if (latitude === undefined || longitude === undefined) {
      return res.status(400).json({
        error: 'Missing required fields: latitude and longitude are required',
      });
    }

    // Call the solar generation API
    const prediction = await predictSolarGeneration(
      latitude,
      longitude,
      month,
      includeLifetime !== false // default to true
    );

    // Extract key fields for your database
    const solarData = {
      location: {
        latitude: prediction.location.latitude,
        longitude: prediction.location.longitude,
      },
      annualGeneration: prediction.annual_summary.year_1_generation_kwh,
      averageDailyGeneration: prediction.annual_summary.average_daily_kwh,
      monthlyBreakdown: prediction.monthly_generation.map(m => ({
        month: m.month,
        monthIndex: m.month_index,
        dailyKwh: m.daily_kwh,
        isDrySeason: m.is_dry_season,
      })),
      lifetimeTotal: prediction.lifetime_prediction?.lifetime_total_kwh || null,
      lifetimeAverageAnnual: prediction.lifetime_prediction?.lifetime_average_annual_kwh || null,
      assumptions: prediction.assumptions,
      confidence: prediction.confidence,
    };

    res.json({
      success: true,
      data: solarData,
    });
  } catch (error) {
    console.error('Solar prediction error:', error);
    res.status(500).json({
      error: 'Failed to get solar generation prediction',
      message: error.message,
    });
  }
});
```

## 7. Error Handling Reference

| HTTP Code | Error Type | Meaning | How Sarah's Backend Should Handle It |
|-----------|-----------|---------|--------------------------------------|
| **400** | Bad Request | Invalid input (missing fields, out-of-range coordinates, invalid month, invalid optional business fields) | Log the error message, return user-friendly validation error to frontend. Do not retry. |
| **401** | Unauthorized | Missing or incorrect `X-API-KEY` header | Check that `SOLAR_API_KEY` environment variable is set correctly. Do not retry until fixed. |
| **429** | Too Many Requests | Rate limit exceeded (100 requests/minute) | Implement exponential backoff and retry. Consider caching predictions for frequently requested locations. |
| **500** | Internal Server Error | Model artifacts missing, server crash, or unexpected exception | Log error, return generic "Service temporarily unavailable" to user. Implement retry with exponential backoff (max 3 retries). Alert DevOps if persistent. |

**Important:** All error responses follow this format:
```json
{
  "status": "error",
  "message": "Human-readable error description"
}
```

For 400 errors with validation details, the response may include:
```json
{
  "status": "error",
  "message": "Invalid input.",
  "details": ["hours_per_day must be between 0 and 24.", "equipment_units must be between 0 and 500."]
}
```

## 10. Known Limitations & Edge Cases

### Input Ranges with Less Reliable Predictions

- **Edge coordinates:** Locations near the boundary of supported region (latitude < -20 or > 2) may have higher uncertainty. The API returns a warning in `coordinate_validation.warnings` for these cases.
- **Outside supported range:** Coordinates outside lat [-26, 6] or lon [-18, 44] will return 400 error. This covers Sub-Saharan Africa but excludes North Africa and Madagascar.

### Geographic Limitations

**Well-supported cities (used in training):**
- Lagos, Nigeria (6.5244, 3.3792)
- Accra, Ghana (5.6037, -0.1870)
- Dakar, Senegal (14.6928, -17.0467)
- Kampala, Uganda (0.3476, 32.5825)
- Nairobi, Kenya (-1.2921, 36.8219)
- Addis Ababa, Ethiopia (9.0320, 38.7469)
- Johannesburg, South Africa (-26.2041, 28.0473)

**Predictions for other SSA locations:** The model generalizes to any coordinates within the supported range, but accuracy may be slightly lower for locations far from training cities.

### What Happens if Location is Outside Supported Range

The API returns a 400 error:
```json
{
  "status": "error",
  "message": "Coordinates are outside the model's calibrated Sub-Saharan Africa coverage (lat: -26 to 6, lon: -18 to 44)."
}
```

Your backend should validate coordinates before calling the API to provide a better user experience.

### Performance Notes

- **Expected response time:** 2-5 seconds for a single prediction
- **With lifetime projection:** Adds ~1-2 seconds (computes 25 years of degradation)
- **Full climatology (12 months):** Takes ~3-6 seconds (predicts all 12 months)
- **Rate limiting:** 100 requests/minute per client IP

**Recommendation:** Cache predictions for common locations (e.g., major cities) to reduce API calls.

## 11. Troubleshooting

### Problem: CORS errors from Node.js

**Symptom:**
```
Access to XMLHttpRequest at 'http://localhost:8000/api/v1/predict-generation' from origin 'http://localhost:3000' has been blocked by CORS policy
```

**Fix:**
1. Verify Flask server has `CORS(app)` enabled (it should be in `solar_climatology_api.py`)
2. Check that you're including `Content-Type: application/json` header
3. If still failing, verify Flask server is actually running and accessible

### Problem: Model file not found (.pkl)

**Symptom:**
```
500 Internal Server Error
{"status": "error", "message": "Internal Server Error"}
```
(Check Flask server logs for `FileNotFoundError`)

**Fix:**
1. Verify these files exist in `models/` directory:
   - `xgboost_climatological_model.pkl`
   - `feature_columns.pkl`
   - `xgboost_climatological_metadata.json`
2. Check `MODEL_DIR` environment variable matches actual directory path
3. If files are missing, contact DSE team to regenerate from training notebook

### Problem: Environment variable not set

**Symptom:**
```
401 Unauthorized
{"status": "error", "message": "Unauthorized"}
```
or Flask server fails to start with error about missing `API_KEY`

**Fix:**
1. Create `.env` file in `models/solar_generation/` with:
   ```
   API_KEY=your_secure_api_key_here
   ```
2. In your Node.js `.env`, set:
   ```
   SOLAR_API_KEY=your_secure_api_key_here
   ```
3. Ensure both values match exactly
4. Restart Flask server after creating/updating `.env`

### Problem: Port conflict

**Symptom:**
```
OSError: [Errno 48] Address already in use
```

**Fix:**
1. Find process using port 8000:
   ```bash
   # macOS/Linux:
   lsof -i :8000
   
   # Windows:
   netstat -ano | findstr :8000
   ```
2. Kill the process or change `PORT` in Flask `.env` to a different port (e.g., 8001)
3. Update your Node.js `SOLAR_API_BASE_URL` to match

### Problem: Dependency version mismatch

**Symptom:**
```
ModuleNotFoundError: No module named 'flask_limiter'
```
or similar import errors

**Fix:**
1. Ensure virtual environment is activated
2. Reinstall dependencies:
   ```bash
   pip install -r requirements.txt --upgrade
   ```
3. Verify Python version is 3.8+:
   ```bash
   python --version
   ```

### Problem: API key header format wrong

**Symptom:**
```
401 Unauthorized
{"status": "error", "message": "Unauthorized"}
```
even though API key looks correct

**Fix:**
1. Verify header name is exactly `X-API-KEY` (case-sensitive)
2. Check for extra spaces or newlines in API key value
3. In Node.js, ensure you're setting header correctly:
   ```javascript
   headers: {
     'X-API-KEY': process.env.SOLAR_API_KEY.trim(), // .trim() removes whitespace
   }
   ```
4. Test with curl to isolate Node.js vs Flask issue:
   ```bash
   curl -H "X-API-KEY: your_key" http://localhost:8000/api/v1/health
   ```
